## E1：现金、股数、订单与公司行为

- 多策略共用一个现金余额。每笔持仓保留策略、版本和信号编号，同代码股数及风险合并；不把重复股票作为不同证券分散风险。
- 同一信号日、同一策略使用首次冻结快照，后续修订或版本不重复投入资金。冻结晚于次日开盘取消入场，收盘前生成的快照拒绝使用。
- 当日入场目标金额固定为前一日完整净资产乘以预先配置的策略预算，再在该次候选之间等分。不成交、部分成交和跳空取消的剩余份额保留现金，不事后扩充其他候选权重，也不补追入场。
- 开盘先处理原持仓退出，再用实际到账现金处理新入场。目标仍由前一完整收盘净资产决定。暂停或退役禁止新增，已经买入的持仓按原规则退出。
- 买入按可配置整数交易单位向下取整，默认 100 股；退出支持剩余整数零股。持仓至少跨一个交易日才能卖出。交易单位模型需要按证券制度进一步验证。
- 流动性限制使用前一交易日成交额乘参与率，同代码当日所有买卖共用该金额限额；可核查的同方向数量上限也在不同策略与持仓批次之间共享。当日最终成交额不会决定当日开盘股数。
- 未复权开盘是参考价，买入执行价格按滑点上浮、卖出下浮；费用按执行金额扣除。现金、费用、滑点与每策略累计损益可以对账。
- 缺失开盘、已核实停牌、开盘不可成交分别记录。退出失败或部分退出持续保留股数，次日继续尝试；不会为得到结束收益而填造退出。
- 已核实分红送转按原持仓处理，应收分红在除权日进入资产，付款后进入现金；卖出持仓不丢掉已有应收款。未知或不支持的已知公司行为持续标记，阻断虚构估值与退出。

支持的模式：

| 模式 | 新增模拟成交 | 证据含义 |
| --- | --- | --- |
| `research_proxy` | 可用已留档开盘代理；已知禁止成交仍尊重 | 原始价格、交易状态、公司行为、分类预算的未知项逐日报告 |
| `verified_inputs` | 未复权价格、开盘状态、公司行为覆盖、分类预算全部满足后才允许 | 核实输入的模拟，仍非真实券商成交，不自动正式使用 |

缺失入场开盘等未知输入不会解释为“有效的零收益现金策略”：保留操作层现金账，但账户效果指标为空，此后同日净超额也为空。已知跳空、预算或停牌取消仍按预先固定的现金处理规则核算。

## E2：净值、换手、暴露与归因

账户每日净资产为 `现金 + 持仓股数×未复权收盘价 + 尚未支付的净分红权利`，净值以初始资金为 1。缺少任一持仓收盘价时整日净值为空，单股最后可知价格仅作提示，不前填为完整估值。缺口后的日收益不跨日拼接；完整区间收益、回撤与波动也保留空值。

每日换手分母固定为上一交易日收盘净资产，首日为初始现金：

```text
买入换手 = 含滑点的买入成交金额 / 分母
卖出换手 = 含滑点的卖出成交金额 / 分母
双边换手 = 买入换手 + 卖出换手
单边约定口径 = 双边换手 / 2
```

费用不计入成交金额。它们都由账户真实模拟股数与资金计算，不再以成交股票数占股票池比例代替。累计账户收益来自每日净值，不将重叠的逐笔收益均值年化；当前不提供年化收益和短样本 Sharpe。

每天报告现金、应收款、合并单股、策略、行业、细分行业、可重叠题材以及流动性暴露。未知分类和未知成交额单列。新增交易受现金保留、单股、策略、行业、题材及流动性预算限制，计算包含费用导致的净资产变化。上涨导致的收盘超限只记录漂移，不强制虚构调仓。

归因按上一收盘持仓拆分：资本市场参考、现金及应收款拖累、已覆盖行业增量、个股与未解释行业残差、执行成本。各项与当日损益可核对；当天新建／退出仓位的开盘到收盘差异留在残差。缺少行业参考时不声称完成行业因果归因。上证综指只作市场参考，不标为可交易的全 A 基准。

另建同池和同板块两个账户，使用相同信号日期、初始资金、策略预算、持有期、整数股数、成本与执行限制，分别保留账户净值和成本后超额。完全相同的篮子保留相同成交优先次序，净超额为零。同板块关系或池成员覆盖不足时阻塞该对照，不把未知关系静默删掉。大篮子中的不足一手份额保留现金，不假装仍是满仓等权。

## 留档与日常操作

预算在加载行情和核算之前登记。改变预算或来源产生不同账户编号；报告、完整输入包和预算不可覆盖，最新索引只是引用。留档目录：

```text
_analysis/daily_pipeline/accounts/configs/      # 账户预算与固定处理政策
_analysis/daily_pipeline/accounts/inputs/       # 完整重放输入包
_analysis/daily_pipeline/accounts/blobs/        # 不可变账本报告及对照
_analysis/daily_pipeline/accounts/by_account/   # 各账户最近一次引用
_analysis/daily_pipeline/accounts/latest.json   # 网页真实前向账户引用
```

报告同时记录账本版本、预算哈希、输入哈希和账本／运行器代码哈希。重跑相同输入、参数和截止时点是幂等的；新资料另存修订，不覆盖旧账。注入测试和 `--inputs` 重放不更新真实前向最新索引。

```powershell
# 读取真实冻结记录和已归档执行输入，不联网、不生成冻结信号
python -m pipeline.account_report

# 账户预算接入日常流程；示例参数未经验证
python -m pipeline.run_daily --account-config docs/examples/account-config.json

# 另存核算到明确的历史截止日
python -m pipeline.account_report --as-of 2026-09-30 --config docs/examples/account-config.json
```

每日采集范围还会保留已冻结账户股票及其对照，即使逐股观察已结束；最早账户信号之前的流动性输入也保留在请求区间。采集失败后账户任务仍运行并显示缺口，恢复时重新读取状态与执行证据。当前按完整输入重放的耗时需在连续运行中检验，后续增量缓存属于 F 的工程维护。

输入字段和可核查覆盖规范见 [账户输入说明](account-input-schema.md)。没有创建定时任务、交易连接或自动策略升级。
