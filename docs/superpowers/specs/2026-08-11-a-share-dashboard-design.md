## 5. 持久化层 (`store.py`)

SQLite 数据库 `data/market.db`。

### 5.1 每日快照
每次拉取大盘/板块数据后,当日快照 upsert 进库,每交易日保留一行(盘中多次覆盖为最新值)。

```
market_daily(
  date TEXT PRIMARY KEY, up_count/down_count/flat_count INTEGER,
  limit_up INTEGER, limit_down INTEGER, total_turnover REAL,
  index_close REAL, snapshot_time TEXT
)
sector_daily(
  date TEXT, type TEXT, code TEXT, name TEXT,
  change_pct REAL, up_ratio REAL, turnover REAL, rank INTEGER,  -- 同 type 内涨幅排名
  PRIMARY KEY(date, type, code)
)
```

**消费方**:
| 指标 | 查询 | 来源表 |
|---|---|---|
| 连续上榜天数 | 连续 count(rank ≤ 20) | sector_daily |
| 板块成交额放量(近5日均值) | 近 N=5 日 turnover 均值 | sector_daily |
| 大盘较昨日量能变化 | 昨日 total_turnover(**仅收盘后**) | market_daily |

**盘中累计值 vs EOD 基准(方法学原则)**:`market_daily`/`sector_daily` 存的是当日累计值最新值,与历史 EOD 值**不可盘中直接对比**(盘中累计必然显示缩量)。**统一口径:凡"当日累计 / 历史 EOD 均值"类指标(大盘量能、板块成交额放量、板块放量滞涨)一律仅收盘后(≥15:00)计算**,盘中对应子项返回缺失、按 §6 归一化降级。分子分母同刻的指标(如资金活跃度=板块/全市场成交额占比)无此问题,盘中可用(A2 + A3' + P2)。**唯一例外:个股自定义量比通过"全日折算"(§7)盘中即可比,不适用此规则(P1)**。

### 5.2 成分股映射(A1' + A2' 核心方案)

**落库**:新增表,成分股映射持久化到 SQLite,跨日不丢:
```
sector_component_map(
  type TEXT, code TEXT, stock_code TEXT,   -- stock_code 为 6 位数字
  refreshed_date TEXT,
  PRIMARY KEY(type, code, stock_code)
)
```

**生命周期**:
- **启动/每日检查**:服务启动时与每日定时,扫描各板块 `refreshed_date`,超过 **5 个交易日**未刷新的板块标记待重建
- **后台构建(M1)**:过期板块的重新拉取在**后台线程**执行,不阻塞请求;**首次运行**全量 465 个板块的后台构建约需 1-3 分钟,期间 UI 标注"成分股数据加载中",构建完成自动刷新
  - **并发限流**:后台构建并发上限 **8**,单请求失败退避重试(同 §9 退避策略),避免触发同花顺风控
  - **写库并发**:SQLite 开 **WAL 模式 + busy_timeout**,后台写与请求线程并发读安全
  - **失败重试**:构建失败的板块**保留旧 `refreshed_date`**,下一轮(每日/下次启动)自动重试;本轮该板块评分降级
- **内存态**:分析层启动时从 SQLite 加载到**独立内存 map**(key=`(type,code)`→股票代码集合),不在 §9 的 200 条内存缓存里 → 消除"200 条上限 vs 465 个映射"的冲突(A1')
- **一致性**:同一板块当天只构建一次;构建中该板块的涨停占比/领涨股按 §6 归一化降级,响应带 `data_complete` 供前端标注

> **首日预算说明(A2')**:§13 的冷启动 30s 预算指**用户可见的按需刷新**;首日成分股全量构建是后台任务,不计入该预算。

## 6. 分析打分层 (`analysis.py`)

通用原则:任何子项数据不可得(冷启动缺历史 / 盘中-EOD 不可比 / 成分股未就绪)→ **从该维度权重池移除该项,剩余项按原比例归一化到 100%**。

### 6.1 大盘总览(无单一情绪结论)
三大指数涨跌、上涨/下跌/平家数、涨停/跌停数、总成交额、较昨日量能变化(盘中 `null`,收盘后有效)。情绪判断落到板块层。

### 6.2 板块打分(板块级情绪)

**板块情绪分**(0-100):板块内上涨家数占比(40%)+ **涨停家数占比(20%,= 涨停数/活跃成分股数,分母取过滤停牌且存在于快照中的成分股数;活跃成分股数为 0 时该子项缺失,走通用归一化降级,M3)**+ 板块成交额放量(25%,**仅收盘后计算**,盘中移除归一化)+ 领涨股强度(15%)

**板块强度分**(0-100):板块指数涨幅(40%)+ 连续上榜天数(30%,同 type 内 rank≤20)+ 资金活跃度(30%,板块成交额占全市场比例,盘中可用)

**板块风险分**(0-100):单日涨幅>5% 或 3日累计>10%(+40)+ **板块放量滞涨(+40,仅收盘后计算,盘中移除归一化,定义见 §7)**+ 板块内严重分化(上涨家数占比<0.35)(+40);封顶 100

> **高风险可达性(B3' + M2)**:三个风险项各 +40,单个警示信号 = 40(中档,轻度警示),任意两个组合 = 80 ≥ 65 = 高风险。"放量滞涨+严重分化"即高位派发形态,不依赖"过热"也能触达高/中档,可触发回避/谨慎追高。

**性能设计(C1)**:全量 465 板块打分用「成分股集合(§5.2 内存 map)∩ 全市场快照(60s 缓存)」在内存 join 计算涨停占比/领涨股,一次快照覆盖全部板块;成分股映射来自 SQLite 内存 map,盘中零重复拉取。

**阈值表(H2)**:
| 维度 | 高 | 中 | 低 |
|---|---|---|---|
| 情绪分 | ≥70 | 45–69 | <45 |
| 强度分 | ≥60 | 35–59 | <35 |
| 风险分 | ≥65 | 40–64 | <40 |

**板块结论规则**(优先级 1→6,先命中先出):
| 优先级 | 条件 | 结论 |
|---|---|---|
| 1 | 强度=低 且 风险=高 | 🚫 **风险提示/回避** |
| 2 | 风险=高 且 (**情绪≥中 或 强度≥中**) | ⚠️ **谨慎追高(过热)**(C5':覆盖"全中+高风险"中间态) |
| 3 | 情绪=高 且 强度=高 且 风险≠高 | ✅ **建议关注** |
| 4 | 情绪=高 且 强度=中 且 连续上榜≥2 且 风险≠高 | 🔶 **跟踪(热点延续)** |
| 5 | 情绪=高 且 强度=中/低 且 连续上榜=1 且 `data_complete=true` | 🚨 **警惕一日游** |
| 6 | 其余 | 👀 **观望** |

**综合评分**:`综合分 = 0.4×强度 + 0.35×情绪 + 0.25×(100−风险)`。榜单按综合分降序,服务端每类 top60 + `search`。

### 6.3 个股量价打分

- **趋势分**:MA5/10/20/60 多头排列、站上 MA20/MA60
- **量价分**:放量突破、自定义量比>1.5 且量价齐升、缩量健康回踩
- **信号分**:MACD 金叉/死叉、突破近期平台高点
- **风险项**:乖离率偏离 MA20>15%、放量滞涨、放量跌破 MA20、高位长上影

> **量比盘中折算(P1)**:量价分与风险项里的量比均用§7 全日折算口径,盘中即可比,不复"上午恒缩量"失真。

**合成规则**:
`个股综合分 = 0.4×趋势 + 0.35×量价 + 0.25×信号`
`个股风险分 = max(各风险项得分)`,单项:乖离率>15% **+70**、放量跌破MA20 **+70**、放量滞涨 +50、高位长上影 +30。**重大风险判定:风险分≥70**(由 +70 两项可达)。

| 综合分 | 无重大风险 | 有重大风险(风险分≥70) |
|---|---|---|
| ≥70 | ✅ **关注** | 🚫 **规避** |
| 55–69 | 🔶 **持有/跟踪** | ⚠️ **回调风险** |
| <55 | 👀 **观望** | 🚫 **规避** |

## 7. 数据口径定义(全部可复现)

- **代码归一化**:全市场快照代码(`sh600000`)与同花顺成分股(6 位)统一为 6 位数字;join 前过滤停牌(成交量为 0 或价格为 0)的股票(C1')
- **change_pct 单位**:全部为**百分比数值**(3.2 = 3.2%,0.45 = 0.45%),全契约统一(A4')
- **自定义量比(P1)**:盘中用**折算全日估算量** `当日累计成交量 × 240 / 已交易分钟数` → 以估算全日量 / 近5日日均成交量;收盘后当日累计量即全日量,公式一致。**非标准分时量比**。
  - **已交易分钟数(A)**:= 当前时间落在 **9:30–11:30** 内的分钟数 + 落在 **13:00–15:00** 内的分钟数;**午休 11:30–13:00 不计入**;9:30 前 = 0,≥15:00 = 240。禁止从 9:30 直接数自然分钟(否则 14:00 会误算 270 分钟,系数错 0.89 vs 1.33)。
  - **最小时长下限(B)**:已交易分钟数 **< 15 时不计算量比**(开盘集合竞价尖峰 ×240 系数会放大 240 倍、量比剧烈抖动误报放量),该子项返回缺失、按 §6 归一化处理。
- **放量 / 缩量**:自定义量比 >1.5 放量,<0.7 缩量
- **多头排列**:MA5 > MA10 > MA20 按序上升
- **站上 MA20**:收盘价 > MA20
- **乖离率**:`(收盘价 − MA20) / MA20 × 100%`
- **个股放量滞涨**:量比>1.5 且 当日涨幅 < 前日涨幅 且 **当日涨幅<2%**(C3')
- **板块放量滞涨(B2' + P2)**:板块成交额 > 近5日均值 且 板块指数涨幅 < 前日涨幅 且 板块指数当日涨幅<2%;**仅收盘后计算**,盘中该风险项移除(当日累计/EOD 均值对比,A3' 同口径)
- **缩量健康回踩**:量比<0.7 且 跌幅≤3% 且 仍站上 MA20
- **高位长上影**:上影线 > 实体 2 倍 且 当日振幅>5%
- **涨停/跌停近似**:主板(60/00)±9.9%、创业板(30)/科创板(688)±19.9%、北交所(8/4)±29.9%;**排除上市≤5 个交易日新股**;ST 不区分,注明"近似值";**涨停占比分母=活跃成分股数**(过滤停牌、且存在于快照中的成分股;北交所票若不在快照则分子分母一并剔除,M3)
- **领涨股强度**:板块成分股中当日涨幅最大的个股涨幅(%)
- **近期平台高点**:当前价 > 前 20 日(不含当日)最高价即突破平台
- **连续上榜排名**:同 type 内排名,"前 20"= 同 type 内 rank≤20

## 9. 缓存实现细节

- **线程安全**:Flask 默认多线程,缓存 dict 用 `threading.Lock` 保护
- **key 规则**:`f"{func_name}:{sorted(params)}"`
- **内存上限**:最多 200 条,超限按插入序淘汰最旧;全市场快照单条最大,命中后 60s 内不重复拉
- **失败退避**:拉取失败返回 stale 缓存,TTL 延长 `30s×2^n`(n=连续失败次数,封顶 10min),成功后重置 n=0
- **成分股映射不在 200 条缓存内**:独立内存 map 启动时从 SQLite 加载,后台按 5 交易日重建(§5.2,A1')

## 10. 错误处理

- 数据源请求超时约 15s,失败重试 1 次
- 重试仍失败 → stale 缓存 + 退避(§9);前端"⚠️ 数据可能过期"
- 首次无缓存且失败 → §8 错误契约,前端明确报错文案
- 参数非法 → 400;数据源挂 → 500
- 同花顺成分股/摘要缺字段、成分股未就绪 → 归一化降级(§6),UI 标注"指标缺失/成分股数据加载中"
