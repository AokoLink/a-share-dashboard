## 5. 持久化层 (`store.py`)

SQLite 数据库 `data/market.db`。每次拉取大盘/板块数据后,**当日快照 upsert 进库**,每交易日保留一行(盘中多次覆盖为最新值)。

**表结构**:
```
market_daily(
  date TEXT PRIMARY KEY,        -- 'YYYY-MM-DD'
  up_count/down_count/flat_count INTEGER,
  limit_up INTEGER, limit_down INTEGER,
  total_turnover REAL,          -- 全市场成交额(元)
  index_close REAL,
  snapshot_time TEXT
)

sector_daily(
  date TEXT, type TEXT,         -- 'industry'|'concept'
  code TEXT, name TEXT,
  change_pct REAL, up_ratio REAL,
  turnover REAL, rank INTEGER,  -- 同 type 内涨幅排名
  PRIMARY KEY(date, type, code)
)
```

**消费方**:
| 指标 | 查询 | 来源表 |
|---|---|---|
| 连续上榜天数 | 连续 count(rank ≤ 20) | sector_daily |
| 板块成交额放量(近5日均值) | 近 N=5 日 turnover 均值 | sector_daily |
| 大盘较昨日量能变化 | 昨日 total_turnover(**仅收盘后计算,见 A2**) | market_daily |

**量能对比方法学(A2)**:`market_daily` 存的是当日累计成交额的最新值,"昨日"是收盘累计值,盘中直接对比必然显示大幅缩量、无意义。**规则:该指标仅收盘后(≥15:00)计算并展示**;盘中返回 `null`,前端显示"收盘后对比"。schema 与"每交易日一行"不冲突。

**冷启动行为(H1 + D2)**:历史数据不足时,历史依赖子项**从对应维度权重池中移除,剩余子项按原比例重新归一化到 100%**(通用降级规则,D3 同此)。缺数据项统一 UI 标注"数据积累中"。逐项:
- 连续上榜天数无数据 → 视为 1 天,且 `data_complete=false`(板块级)
- 板块成交额均值/昨日量能无数据 → 对应子项移除归一化
- **板块风险分的"3日累计涨幅""放量滞涨"同样依赖历史**(D2)→ 冷启动跳过,风险分只按可计算子项归一化构成
- 运行 5 个交易日后历史指标自动恢复完整

## 6. 分析打分层 (`analysis.py`)

通用原则:任何子项数据不可得 → 从该维度权重池移除该项,剩余项按原比例归一化(D3)。

### 6.1 大盘总览(无单一情绪结论)
三大指数涨跌、上涨/下跌/平家数、涨停/跌停数、总成交额、较昨日量能变化(盘中 `null`,收盘后有效,见 A2)。情绪判断落到板块层。

### 6.2 板块打分(板块级情绪)

**板块情绪分**(0-100):板块内上涨家数占比(40%)+ 板块内涨停家数(20%)+ 板块成交额放量程度(25%)+ 领涨股强度(15%,定义见 §7)

**板块强度分**(0-100):板块指数涨幅(40%)+ 连续上榜天数(30%,同 type 内 rank≤20,见 E2)+ 资金活跃度(30%,板块成交额占全市场比例)

**板块风险分**(0-100):单日涨幅>5% 或 3日累计>10%(+40)+ 放量滞涨(+30)+ 板块内严重分化(上涨家数占比<0.35)(+30);封顶 100

**性能设计(C1)**:榜单要排 top60,需给全部 90+375=465 个板块打分,不能逐板块拉行情。**方案**:涨停家数与领涨股强度改用「板块成分股代码集合 ∩ 已拉取的全市场快照(60s 缓存)」在内存 join 计算——快照已含每只票涨跌幅,一次快照覆盖全部板块;成分股映射走交易日级缓存(§4),盘中零重复拉取。

**阈值表(H2)**:
| 维度 | 高 | 中 | 低 |
|---|---|---|---|
| 情绪分 | ≥70 | 45–69 | <45 |
| 强度分 | ≥60 | 35–59 | <35 |
| 风险分 | ≥65 | 40–64 | <40 |

**板块结论规则**(优先级 1→6,先命中先出):
| 优先级 | 条件 | 结论 |
|---|---|---|
| 1 | 强度=低 且 风险=高 | 🚫 **风险提示/回避** |
| 2 | 风险=高 且 (情绪=高 或 强度=高) | ⚠️ **谨慎追高(过热)** |
| 3 | 情绪=高 且 强度=高 且 风险≠高 | ✅ **建议关注** |
| 4 | 情绪=高 且 强度=中 且 连续上榜≥2 且 风险≠高 | 🔶 **跟踪(热点延续)**(D1) |
| 5 | 情绪=高 且 强度=中/低 且 连续上榜=1 且 `data_complete=true` | 🚨 **警惕一日游**(B1:冷启动首日 data_complete=false 不触发,落观望) |
| 6 | 其余 | 👀 **观望** |

**综合评分**:`综合分 = 0.4×强度 + 0.35×情绪 + 0.25×(100−风险)`。榜单按综合分降序,服务端每类 top60 + `search`(E5)。

### 6.3 个股量价打分

- **趋势分**:MA5/10/20/60 多头排列、站上 MA20/MA60
- **量价分**:放量突破、自定义量比>1.5 且量价齐升、缩量健康回踩
- **信号分**:MACD 金叉/死叉、突破近期平台高点
- **风险项**:乖离率偏离 MA20>15%、放量滞涨、放量跌破 MA20、高位长上影

**合成规则(H5 + A1)**:
`个股综合分 = 0.4×趋势 + 0.35×量价 + 0.25×信号`
`个股风险分 = max(各风险项得分)`,单项分值:乖离率>15% **+70**、放量跌破MA20 **+70**、放量滞涨 +50、高位长上影 +30。**重大风险判定:风险分≥70**(由 +70 两项可达,阈值不悬空,修复 A1 死代码)。

| 综合分 | 无重大风险 | 有重大风险(风险分≥70) |
|---|---|---|
| ≥70 | ✅ **关注** | 🚫 **规避** |
| 55–69 | 🔶 **持有/跟踪** | ⚠️ **回调风险** |
| <55 | 👀 **观望** | 🚫 **规避** |

## 7. 数据口径定义(全部可复现)

- **自定义量比**:`当日成交量 / 近5日日均成交量(不含当日)`。**非标准分时量比**。
- **放量 / 缩量**:自定义量比 >1.5 为放量,<0.7 为缩量(E6)
- **多头排列**:MA5 > MA10 > MA20 按序上升(E6)
- **站上 MA20**:收盘价 > MA20(E6)
- **乖离率**:`(收盘价 − MA20) / MA20 × 100%`
- **放量滞涨**:量比>1.5 且 当日涨幅 < 前日涨幅 且 涨幅<2%(E6)
- **缩量健康回踩**:量比<0.7 且 跌幅≤3% 且 仍站上 MA20(E6)
- **高位长上影**:上影线 > 实体 2 倍 且 当日振幅>5%(E6)
- **涨停/跌停近似**:按涨跌幅阈值近似,无封板状态;主板(60/00)±9.9%、创业板(30)/科创板(688)±19.9%、北交所(8/4)±29.9%;**排除上市≤5 个交易日的新股**(首日及注册制前5日无涨跌幅限制,E7);ST 不区分,注明"近似值"
- **领涨股强度**:板块成分股中当日涨幅最大的个股涨幅(%)
- **近期平台高点**:当前价 > 前 20 日(不含当日)最高价即突破平台
- **连续上榜排名(E2)**:同 type 内排名(行业在 90 个行业内、概念在 375 个概念内分别排名),"前 20"= 同 type 内 rank≤20

## 9. 缓存实现细节(M3)

- **线程安全**:Flask 默认多线程,缓存 dict 用 `threading.Lock` 保护
- **key 规则**:`f"{func_name}:{sorted(params)}"`
- **内存上限**:最多 200 条,超限按插入序淘汰最旧;全市场快照单条最大,命中后 60s 内不重复拉
- **失败退避**:拉取失败返回 stale 缓存,TTL 延长 `30s×2^n`(n=连续失败次数,封顶 10min),成功后重置 n=0
- **成分股映射**:交易日级缓存(§4),当日首次拉取后到收盘不再重复请求

## 10. 错误处理

- 数据源请求超时约 15s,失败重试 1 次
- 重试仍失败 → stale 缓存 + 退避(§9);前端"⚠️ 数据可能过期"
- 首次无缓存且失败 → §8 错误契约,前端明确报错文案
- 参数非法 → 400;数据源挂 → 500(§8)
- 同花顺成分股/摘要缺字段 → 归一化降级(§6),UI 标注"指标缺失"
