# P0：价格覆盖与每日运行稳定性

> 实施日期：2026-09-30—2026-10-01。本文记录程序实现和真实采集验收；连续十个实际交易日不能由同日重复运行或测试替代。

## 改动范围

新增 `core/price_collection.py`，每日任务继续先确定完整资格范围，再采集双价格并确认资格，最后才截断为研究池。持仓、已冻结对照和账户相关证券仍加入请求清单，不因本日流动性排名变化丢失。

- **首次历史补齐**：按默认约 400 个自然日请求技术与未复权价格；账户所需窗口更早时扩展请求起点。
- **跨运行缓存**：只复用哈希完整、口径相同、来源模式相同且覆盖所需请求窗口的输入。真实来源和注入测试使用不同缓存目录；未来日期缓存不能切片充当前一日的真实输入。
- **每日增量**：从最后可用日之前十个交易日开始请求，校验重叠窗口，合并新增日期；历史缺日时将补采起点前移到最早缺口。
- **复权与修订**：重叠价格／量额发生变化、来源改变或没有重叠时，重新采集整段窗口，不把旧复权历史与新基准拼接。该检查不能证明来源从未修订重叠窗口之外的历史，可用强制刷新定期核验。
- **失败恢复**：传输错误最多重试一次，退避后重新请求；字段或价格校验错误直接记录。运行 checkpoint 和跨运行缓存共同恢复，已成功且完整的当日输入无需重复访问来源。
- **不可变留档**：每次采集尝试在独立目录保存响应、价格与依赖引用。补采不覆盖作为父输入的旧价格；执行入口的可变文件可从核验过的档案重建。
- **限速与进度**：价格来源调用按间隔发起，工作线程上限仍为八；运行进度及 checkpoint 定期保存，避免每个输入都重写整个清单。

## 来源缺口修正

腾讯响应的 `day` 和 `qfqday` 严格区分。对只返回 `day` 的前复权请求，独立读取新浪明确返回的前复权因子：检查证券标识、数量、重复日期、有限正值及历史覆盖，按相对因子转换 OHLC，量额保持原值。因子原始对象另存并纳入内容哈希依赖。

没有因子证据时不假设因子为 1；没有所请求的未复权口径时不使用复权价代替。因子仅用于技术价格构造，不能当成执行状态或完整公司行为账本。来源 JSON 只解析，不执行返回的 JavaScript。常规窗口使用单次腾讯请求，避免同一历史范围按年份重复拉取。

实际扩大范围采集发现 21 只 `920` 股票被旧前缀规则误识别为上海证券，导致 42 份双价格缺失。现修正为北交所 `bj` 前缀，保留 `900` 上海 B 股识别，并让 `920` 使用与已有北交所代码相同的描述性涨跌幅阈值。依据：[北交所代码公告](https://www.bse.cn/important_news/200021617.html)、[北交所交易规则](https://www.bse.cn/jygl_list/200028217.html)。描述性阈值不代替已核实的逐证券涨跌停执行价格或新股例外证据。

## 运行与恢复

```powershell
python -m pipeline.run_daily --workers 6
python -m pipeline.run_daily --resume <当日运行编号> --workers 6
python -m pipeline.run_daily --refresh-prices --workers 6
```

同日恢复要求代码、预算、持仓和模式一致。代码或日期变化时开始新运行，已校验的跨运行缓存仍可复用。`--refresh-prices` 跳过缓存，对全部请求证券重新核验历史；它也是运行签名的一部分。

运行目录的 `price_progress.json` 保存完成数和失败数，`price_retry_queue.json` 保存失败或过期输入及原因，`price_history_gaps.json` 单列未解释的历史缺日；根目录 `price_retry_latest.json` 指向最新失败补采清单。`health.json` 记录采集模式、采集尝试次数、错误分类和最近成功日，并区分本次请求与旧范围证券。

每日报告分别保留整条任务连续完整日数和价格覆盖连续完整日数。价格覆盖按当日输入和既有质量步骤计数，不证明历史每个交易日均已核实；未解释历史缺日另行报告。价格完成不等于板块特征、策略有效性或执行状态完成；旧报告、观察模式和注入测试不能提高真实连续运行计数。本次未创建定时任务。

来源缺日继续标记为未知停牌或数据缺口，不补零、不前填成交价格。扩大后的首次补齐需要实际来源请求；连续十个实际交易日、精确板块关系及已核实交易状态需要后续真实证据，不能由缓存、重复运行或手工案例代替。
