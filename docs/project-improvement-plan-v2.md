## 一、当前判断与本轮目标

项目已经具备行情看板、板块与个股分析、独立技术策略、组合风险透视，以及冻结信号和前向观察的基本框架。本轮目标是提升现有功能的正确性，使数据采集、选股、执行核算与效果评估能够连续运行，并让在线展示与历史研究使用一致口径。

截至本次核查：

- 真实数据库中冻结信号、前向观察和策略状态事件均为 0 条，尚未形成真实前向证据。
- 第一阶段可校验的未复权日线覆盖 13 只主题核心股，尚不足以支撑当前最多 200 只股票的策略研究池及其对照。
- 历史成分、含退市证券的完整股票池、历史 ST／停牌／涨跌停状态、公司行为核账四项正式数据门槛仍未通过。
- 三套技术策略可以产生研究候选，但尚不能证明稳定的成本后选股增量；中期配置仍缺少按披露日期可用的财务数据。
- 本次评估新发现缓存过期标识、前向净收益对照和策略状态执行约束等问题，需要先修正。

前四阶段的实施记录仍保留为历史依据。本文件作为后续工作清单，任务编号采用 A—F，避免与原四阶段编号混淆。

## 三、批次 A：先修正结果可信度

### A1. 分开数据新鲜度与失败重试时间

**现状：**`TTLCache.mark_failure()` 会重置缓存时间并延长 TTL。最小复现表明，同一份过期数据在失败处理后，`get()` 返回的 `fresh` 会由 `False` 变为 `True`；上层可能把旧值当作新鲜数据。

**改进策略：**

1. 分别保存最近成功采集时间、数据截止时间、下次允许重试时间和失败次数。
2. 重试退避只控制何时请求来源，不改变旧数据的截止时间和过期状态。
3. 行情、板块、市场环境与候选接口统一传播来源失败及过期信息。
4. 只有新的成功采集通过数据质量校验后，才解除相应的过期状态。

**验收标准：**复现“缓存过期 → 来源失败 → 退避期间再次请求 → 来源恢复”完整过程；失败期间始终标记过期，恢复后才更新。过期来源不能被第四阶段冻结为完整的新鲜信号。

**涉及位置：**[数据源与缓存](../core/data_source.py)、[新鲜度判断](../core/freshness.py)、[策略接口](../web/routes/strategies.py)。

### A2. 统一收益、基准与指标含义

**现状：**前向评审以策略净收益减去股票池或板块基准毛收益，口径不一致；`turnover_one_way` 当前为模拟成交股票数除以股票池数量，不能表示账户换手。

**改进策略：**

1. 策略与各基准同时保存毛收益和净收益，分别计算毛超额、净超额。
2. 采用统一的费用、滑点及成交规则，记录成本模型版本；成本参数的差异必须有明确依据。
3. 将成交数量占股票池比例改为符合含义的名称；真实账户换手在 E 批次由交易金额与净资产计算。
4. 分开展示成交率、未成交原因、持仓覆盖率和数据覆盖率。
5. 对旧观察保留原始记录和计算版本；修正结果另存，页面标明可比较的口径。

**验收标准：**当策略与基准选择完全相同、权重和成交条件相同时，净超额为零；毛收益、费用、滑点和净收益可以对账；指标名称与计算公式一致。

**涉及位置：**[前向跟踪与评审](../core/strategy_lifecycle.py)、[历史策略评估](../pipeline/evaluate_strategies.py)。

### A3. 让暂停与退役状态约束实际流程

**现状：**暂停、退役可以写入状态事件，但候选生成接口没有读取这些状态来控制该版本是否继续进入正常流程。

**改进策略：**

1. 建立共享的策略运行许可检查，供页面、命令行和后续每日任务使用。
2. 暂停或退役版本退出正常候选和新增模拟建仓流程。
3. 如果需要继续研究，显式启用仅观察模式，独立标记结果，不与正常运行样本混合。
4. 已冻结信号、已有持仓及历史观察仍可查询；已有持仓如何退出由原执行规则和状态变更原因决定，不能直接删除。
5. 状态变化保存时间、原因及证据引用，恢复运行也必须留下事件。

**验收标准：**在所有入口中，暂停和退役规则一致生效；已有记录可追溯；仅观察模式与正常运行结果明确区分。

**涉及位置：**[状态事件存储](../core/store.py)、[候选生成](../web/routes/strategies.py)、[状态变更命令](../pipeline/set_strategy_status.py)。

## 四、批次 B：建立每日数据与验证流程

### B1. 统一每日任务入口

建议的依赖顺序为：

**交易日与时间检查 → 行情更新 → 数据质量检查 → 市场环境和板块特征更新 → 当日候选冻结 → 已有信号的执行与结果跟踪 → 现金持仓账户核算 → 日报。**

具体方案：

- 每次运行分配唯一运行编号，保存各步骤的开始时间、结束时间、输入日期、结果和异常。
- 区分休市跳过、尚未收盘、正常无候选、部分成功和数据故障，避免统一显示成“没有信号”。
- 支持幂等重跑、失败步骤续跑以及单实例执行，防止重复写入和并发采集冲突。
- 根据交易日历和来源实际更新时间决定触发时机，不能仅以本机时间超过 15:05 作为数据已齐备的证据。
- 后台任务负责采集和计算，页面读取结果与运行状态。
- 完成单次运行和重跑验收后，再配置定时运行；本方案文档本身不创建定时任务。

### B2. 数据覆盖从固定样本扩展到实际使用范围

1. 明确每日研究池、基准池和已有持仓的代码清单，统计每项输入的应有数量与实际数量。
2. 扩展未复权价格、技术计算价格、成交量额、板块归属和交易状态覆盖；技术价格与执行价格分别管理。
3. 保存原始响应或规范化数据、来源、采集时间、行情截止时间、字段单位和哈希。
4. 对重复日期、日期逆序、异常价格、缺失交易日和字段变更建立检查。缺失行情不能直接推断为停牌。
5. 为市场环境和板块特征同步更新输入，避免个股日线新鲜而环境缓存过期。
6. 当前成分快照只支持观察日及有证据的有效区间；历史成分、退市股和交易状态档案单独补齐，不回填假设值。

### B3. 在事件发生时记录执行进度

当前跟踪器会先等待完整持有期到达，再计算结果。后续应按当时已经可知的信息记录“等待入场、取消、模拟成交、持仓中、等待退出、已退出、数据异常”，在 T+1 即可查看入场情况，而不必等待最终收益。

**验收标准：**先连续覆盖至少 10 个实际交易日，作为运行稳定性检查；每个预期任务都有结果或明确原因，断点恢复不重复冻结。该检查不代表策略有效。所有候选及对照的缺失率可查；尚未到期、停牌待核实和来源故障不会混为一种状态。

**涉及位置：**[采集入口](../pipeline/collect_stage1.py)、[冻结入口](../pipeline/freeze_strategy_signals.py)、[跟踪入口](../pipeline/track_strategy_signals.py)。

## 五、批次 C：让板块分析进入选股流程

### C1. 统一行业、细分行业与题材关系

板块页、策略筛选和组合暴露共用一套关系查询，返回分类类型、代码、来源、观察日期、生效区间及覆盖率。行业与可重叠题材分别展示；映射不确定时给出未知状态。

先保存今后每日真实观察到的关系，再补充可验证的历史变更档案。新的当前映射不应反写旧信号使用的板块关系。

### C2. 扩展轮动与内部广度

当前轮动矩阵先取当日涨幅较高板块，可能遗漏尚未明显上涨但中期结构较强的方向。应先建立完整可用板块集合，再按多周期相对强度、内部广度、成交集中度及持续性筛选和展示。

建议分步增加：

- 5/20/60 日相对强度、排名和排名变化；标明所用基准，上证综指不标成全 A 市场。
- 上涨比例、成员收益中位数、站上均线比例、创新高比例；只在成分及行情覆盖达到预先约定条件时展示完整广度。
- 领涨股与普通成员表现差异、成交额前三占比，以及这些指标的历史变化。
- 对“启动观察、内部扩散、明显分化”等标签先验证描述的一致性，再检验是否改善未来选股。

### C3. 完成板块条件与龙头角色的衔接

目前突破策略支持 `sector_rel20`，但在线与历史筛选没有实际提供该值。应使用同一截止日、同一成员口径计算板块特征，并同时接入两条路径；缺少数据时明确区分不适用和无法验证。

价格领涨目前仅检查最多 10 只成分样本，应逐步扩展覆盖，统一个股与板块的比较日期，加入领涨持续性和跟随广度。成交核心、价格领涨与产业核心继续分开；产业核心依赖财务和业务证据。

**验收标准：**给定某日某只候选，可以还原其板块归属、板块特征、数据截止日及缺失处理方式。轮动矩阵明确候选板块范围，龙头列表明确成分覆盖。板块特征加入前后的差异可进入 D 批次对照实验。

**涉及位置：**[板块分析](../core/sector_insights.py)、[板块接口](../web/routes/sectors.py)、[策略定义](../core/strategies.py)、[组合接口](../web/routes/portfolio.py)。

## 六、批次 D：统一选股流程并重新验证策略

### D1. 在线与历史共用完整流程

目前双方虽然共用 `strategies.screen`，但在线先从现货筛成交额前 200，再检查历史资格；历史评估先检查资格，再取前 200。需要统一以下顺序和规则：

**按日数据视图 → 基础资格 → 股票池排序与截断 → 市场及板块条件 → 策略触发 → 策略内排序 → 冻结结果。**

基础资格、截止日期、缺失字段处理、并列排序及截断规则均只定义一次。来源覆盖不足时允许结果不同，但必须产生可解释的差异报告。

**验收标准：**在相同日期、输入、参数和版本下，在线与历史得到相同的资格结果、候选池、排序和入选理由；改变未来行情不会改变这些结果。

### D2. 按策略假设安排实验

| 策略 | 本轮研究重点 | 必须保留的对照 | 推进条件 |
| --- | --- | --- | --- |
| 趋势突破 | 分别检验板块强度、突破幅度和量能条件的增量，识别假突破及跳空影响 | 同池等权、同板块等权、板块内随机、去除单个条件的版本 | 独立区间和前向观察显示成本后增量，且风险可接受 |
| 强势回调 | 检查回调结构、缩量条件以及不同市场环境下的稳定性 | 同池及同板块对照；同环境下的突破版本 | 改善不是只来自某个时间段或风格暴露 |
| 超跌反弹 | 按独立恐慌事件评估，检验选个股是否优于同日基础篮子 | 同日等权、宽基参考及事件簇等权统计 | 多个独立事件支持结论，结果不由少数极端日期主导 |
| 中期配置 | 先建立按实际披露时间可用的财务、估值和行业证据 | 简单估值／质量基准、价格动量基准 | 数据时点可核查后才定义和测试选股规则 |

现有探索性结果中，突破与回调整体未胜过对照；反弹的 25 个信号日合并后仅 13 个事件簇。以上是研究边界，不能直接作为调参目标或有效性证明，详见[第二阶段记录](phase2-strategy.md)。

### D3. 规范实验与评审

1. 实验开始前记录假设、股票池、参数、成本、持有期、对照、主要指标及停止条件。
2. 保留未参与方案设计的验证区间；滚动验证按收益标签结束日处理隔离。
3. 新条件逐项加入，报告加入前后变化，并保留负结果。
4. 对相邻或重叠信号按事件簇或时间块统计，报告不确定性；信号条数不等于独立样本数。
5. 检查成交额、波动、规模等风格差异。缺少历史字段时明确保留未解释暴露。
6. 报告成交条件下的选股收益与账户实际资金收益，避免把未成交或失去行情的样本静默删除。
7. 现有“60 个观察日、30 个事件簇”等数量门槛仅作为研究流程门槛；达到数量且平均超额为正，仍不足以单独证明有效。

**交付物：**共享筛选引擎、逐日一致性报告、实验登记表、同口径基准结果，以及按环境和事件分组的验证报告。

## 七、批次 E：账户组合核算与风险预算

### E1. 建立现金、股数与交易事件账本

逐股收益均值不足以代表一个账户。账本至少记录信号、目标权重、订单、成交、撤单、现金、持仓股数、估值和公司行为事件。

执行规则应明确：

- 未成交资金保留现金，或按事先固定的规则分配；不能在看到最终收益后重新分配。
- 多日重叠信号和跨策略重复股票共享明确的资金预算，不重复使用同一笔现金。
- 使用未复权成交价，并按已验证的分红送转事件处理现金和股数。
- 缺失开盘、停牌及涨跌停可成交性分别处理；无法核实的成交留在研究代理层。
- 不能成交的退出单保留状态与风险敞口，不能为了完成回测而虚构退出。

### E2. 以账户时间序列计算指标

1. 根据每日现金和持仓市值生成净值，再计算回撤、收益和风险；不直接将重叠持有期的逐笔收益年化。
2. 分别报告买入额／净资产、卖出额／净资产和约定口径的总换手，明确分母与时间。
3. 记录单股、行业、题材、策略、现金及流动性暴露；跨策略重复代码先合并账户风险。
4. 在同一日期、资本和执行假设下拆分市场、板块、个股、仓位及执行成本贡献。
5. 风险预算先作为可配置约束接受验证，不把历史最优权重直接作为当前目标仓位。

**验收标准：**用少量可人工核对的案例验证等权持仓、部分成交、跳空取消、持仓重叠、退出失败和分红送转。每一日的现金、股数、市值与净值可核对，未来行情不会改变过去账本。

**涉及位置：**[当前前向模拟](../core/strategy_lifecycle.py)、[已有主题账户核算](../pipeline/theme_vol_strategy.py)、[组合风险分析](../core/portfolio_insights.py)。

## 八、批次 F：页面流程、版本与工程维护

### F1. 围绕实际研究流程组织页面

建议统一为“市场环境 → 板块方向 → 策略候选 → 组合风险 → 验证记录”。梳理推荐、可介入龙头、波段等旧入口的职责，统一证据等级和术语。

每个候选应直接回答：数据截止何时、为何入选、归属哪个策略、什么条件失效、最早何时可执行、与已有持仓是否重复。研究指标与通过验证的用途分开呈现。组合页面逐步支持真实权重和现金输入，并说明当前权重来自实际输入还是等权假设。

### F2. 分开管理规则、数据与执行版本

当前冻结版本将整个路由文件纳入指纹，普通接口改动也可能产生新策略版本；部分共享依赖又不在该指纹中。建议保存结构化版本清单：

- 策略规则、资格过滤和参数版本。
- 数据、板块关系、市场环境及特征计算版本。
- 交易执行、成本模型、账户核算和评估版本。
- 应用与页面版本。

保存实际计算用的历史窗口或不可变数据引用、内容哈希及对应代码版本。前复权历史后续修订时，仍能重放当时的候选与分数。仅保存哈希而没有可取回的数据和代码，不算完整复现能力。

### F3. 降低接口负担并补齐运行监控

- 页面查询与冻结写入分开；采集和批量计算从页面请求中移到后台任务。
- 对日期、策略和版本建立结果缓存；监控记录分页查询，避免每次读取全部历史。
- 保存逐代码失败原因、来源耗时、覆盖率和最后成功日期，减少只有汇总失败数的情况。
- 为来源字段变更、任务中断、重复执行、数据过期和状态切换补充关键验证。
- 整理依赖、版本留档和数据库备份恢复流程，保留既有快照与状态事件。

**验收标准：**普通页面改动不会重置策略观察期；策略关键依赖变化可识别；任一冻结记录可重放。页面刷新不重复执行整池采集，失败步骤和恢复方法可查。

## 九、第一批可执行任务清单

- [x] A1：修复缓存失败退避与新鲜度混用，补充完整失败恢复场景验证。
- [x] A2：统一毛／净收益基准，修正换手字段名称并保留旧结果供对照。
- [x] A3：将策略状态检查接入阶段二候选入口和前向新增模拟建仓。
- [x] B1：建立每日任务入口、运行编号、日志和幂等重跑。
- [x] B2：输出当前候选、对照和已有持仓的逐代码数据覆盖清单。
- [x] B3：将执行进度与最终持有期收益分开记录。
- [ ] B 运行验收：至少 10 个连续实际交易日完成任务与覆盖核查；真实缺失和来源故障继续补齐。
- [x] 后续 P0 程序：首次价格补齐、跨运行缓存、每日增量、复权检查、限速与失败恢复已接入，见[P0 实施记录](p0-data-stability.md)。扩大范围的实际覆盖和未解释历史缺日单独记录，十日验收仍需真实积累。
- [x] C1：建立共用的带日期板块关系查询。
- [x] C2—C3：扩大轮动覆盖，统一截止日，并接入板块强度特征。
- [ ] C 数据与研究验收：精确三类关系、当日指数／基准、完整成员价格及历史关系档案继续补齐；选股增量进入 D 检验。
- [x] 后续 P1 程序：原生成员枚举、上证基准、独立前向登记／隔离、来源证据导入、逐证券数量及费用核算已接入，见 [P1 实施记录](p1-evidence-and-validation.md)。本轮 330 个分类通过枚举、155 个申万同源指数及 90 个同花顺指数留档，官方分类历史 12,925 条保存；历史时点完整性、22 只来源覆盖外证券、真实执行输入和未来样本单独待验收。
- [x] D1：统一在线与离线股票池及完整筛选流程。
- [x] D2—D3：冻结实验方案，按同日对照和独立事件重新评估。
- [ ] D 数据与独立验证验收：补齐扩大后的输入范围、历史关系和交易口径，积累登记后未参与设计的前向样本；不依据已看过的历史或数量门槛升级。
- [x] E1—E2：接入现金持仓账本、已核实公司行为、账户净值、资金换手、同资本对照和风险预算。
- [ ] E 数据与账户验收：积累真实冻结信号与每日账户，补齐执行状态、公司行为及分类覆盖；复杂公司行为和实际交易制度继续核账。
- [x] F1—F3：完成新冻结输入与代码归档、独立重放、主页面流程、分页与故障监控、备份恢复和维护说明，见[步骤 F](step-f-implementation.md)。
- [ ] F 历史与运行验收：旧记录缺少的原始输入／代码不能补造；继续验证扩大输入后的耗时、连续运行和部署恢复。

完成每项时，在相应实施记录中登记修改范围、验证方式、结果及剩余限制；不因功能接口已经存在就认定其数据和研究验收已经通过。
