# 步骤 F：使用流程、版本归档与工程维护

> 实施日期：2026-09-30。F1—F3 的程序与文档已实施；历史资料不齐、连续运行和策略有效性仍按 B—E 的数据门槛验收，不因工程改造而升级。

## F1：研究流程和界面

主导航按“市场环境 → 板块方向 → 策略候选 → 组合风险 → 验证记录”组织。旧推荐、可介入龙头、波段、主题策略与诊断等归入其他研究工具，说明各自职责，保留既有接口。

独立候选只读取后台结果，展示截止时间、策略、板块证据、原因、失效条件、最早执行及与保存账户持仓是否重复。没有账户时显示未知，不把未知视为没有持仓。研究候选与策略使用等级分开。

组合页面可填写实际股票权重与现金，校验总和为 100%，按代码合并重复权重；未填则继续使用自选等权，并标明假设。原账户模拟与输入持仓的风险分析分开，填入实际权重不会篡改模拟账本。

## F2：分层版本和完整重放包

新增 `core/version_manifest.py`，区分筛选规则与资格依赖、数据与特征、执行与评估、应用与页面四层。新快照保留各层文件哈希与 Python／主要依赖版本。筛选身份补上原来遗漏的 `core.analysis` 资格阈值及环境依赖；此次关键依赖清单改变会产生一次新指纹，原冻结版本和观察不迁移。页面、路由或账户展示修改不进入筛选身份。

新增 `core/signal_replay.py`，后台冻结前保存完整输入和对应源文件字节，不只保存指向可变路径的哈希。包、代码、输入按内容寻址且不可覆盖；恢复续跑检查归档依赖完整性。重放使用归档代码的独立 Python 进程，禁止网络和新冻结，比较整个筛选决定及候选。

## F3：查询、监控和维护

- 监控快照采用有界游标分页，观察只取该页快照的最新记录，并增加相应数据库索引。版本评审在后台计算，数据库水位变化时摘要标为过期。
- 候选和保存报告使用 64 项有界文件缓存，按文件位置、修改时间、长度及预期内容哈希区分；返回副本防止一次请求改变缓存。策略状态仍从数据库读取，不让缓存绕过暂停。
- 日常任务及双口径价格来源记录耗时，保留逐代码错误、最后成功日和恢复说明，监控页面读取故障清单。旧运行没有耗时字段时不虚构数据。
- 新增 SQLite 在线备份、数据与源文件 ZIP、逐文件哈希和新目录恢复验收。备份受每日任务锁约束，恢复保留原数据库与快照，路径映射不改变不可变内容。
- 直接依赖声明补全 numpy、requests，保存实际验证环境 41 项依赖锁文件。运行、恢复、重放与部署重启说明见 [运行维护说明](operations.md)。
