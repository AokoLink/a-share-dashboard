# 候选自动生成与按钮保底

实施日期：2026-10-09。

## 使用方式

按原方式运行 `python app.py`，看板服务同时启用每日调度。上海时间交易日 15:05 后启动后台任务，每 30 秒检查一次；如果五点才启动服务，当天 23:00 前会补执行。交易日按已保存的真实日历判断，不把工作日直接当交易日。

策略候选页新增 **生成今日候选** 按钮，与自动任务启动同一条后台流程。原 **读取候选** 仍只查询保存结果。收盘前和已确认休市日不能启动生成；日历缺失或超出覆盖时，自动任务不猜测，手动按钮可启动后台日历刷新，原每日任务仍会再次核实交易日和收盘门槛。

页面显示自动启用状态、任务日期、排队／运行／完成／部分完成／失败及各步骤进度，每 5 秒查询一次。任务运行中按钮禁用；完成后自动刷新候选与市场环境。没有股票入选属于正常完成。失败或部分完成后，按钮变为重试入口，保留原任务记录。

收盘前按钮明确显示“等待 15:05（今日候选）”，状态展示上海服务器时间和禁用原因，避免看起来可点击但没有响应。该按钮不会补算昨日；没有保存的昨日候选不因刷新而出现。

**看板服务必须保持运行，电脑需处于唤醒状态，才能到点启动自动任务。** 这是应用内调度，没有安装 Windows 系统计划任务或 Codex 定时任务。后台任务一旦启动，就在独立 Python 进程运行；关闭浏览器不影响任务，正常关闭看板服务也不主动终止该进程。服务关闭期间错过的日期不会在次日补成真实前向信号。

部署本次修改后重启看板，并用 Ctrl+F5 重新加载页面。自定义 WSGI 启动若调用 `create_app()`，默认不启动调度；需显式使用 `create_app(start_daily_scheduler=True)`。测试应用工厂默认关闭调度，避免测试或导入应用意外触发生产采集。

## 防重与恢复

- 自动调度每天最多尝试一次；失败不会每 30 秒反复采集，可通过按钮重试。
- 自动任务、重复点击、多个看板进程共享文件锁及持久化日记录；已有任务运行时复用状态。原每日任务锁继续阻止与命令行任务同时写入。
- 当天完整任务已经完成时，不再次生成；命令行完成的当天任务也会被识别。
- 后台进程按 PID 加创建时间核对，避免 PID 被复用后误判。进程退出但任务状态未完成时标为中断，可手动重试。
- 每次尝试保留独立编号，任务状态与日志在 `_analysis/daily_pipeline/automation/jobs/<编号>/job.json`、`worker.log`；日索引和最近任务引用位于 `automation/days/`、`automation/latest.json`。原运行细节仍在 `runs/<运行编号>/`。
- 新后台进程执行前检查实际日期，不允许把跨日启动或今日运行记成昨日信号。23:00 后不再启动新任务，已启动任务继续执行，原冻结规则仍检查实际封印时刻。
- 环境检查点独立于板块步骤留档，板块失败时已验证环境仍能读取。跨日恢复只显示为历史研究补算，保留原失败状态及实际补算时间。详见 [2026-10-09 自动任务失败修复](daily-task-nan-fix-2026-10-10.md)。

## 接口与代码

`GET /api/daily-job` 读取任务状态和当前自动门槛，不启动采集。`POST /api/daily-job` 提交空 JSON 对象启动后台任务，立即返回，页面不等待整池采集。任务只处理实际当天，不能通过请求指定任意日期、文件路径或 Python 命令。

实现位置：`core/daily_jobs.py` 为共享调度与持久状态，`pipeline/run_daily_job.py` 为独立工作进程，`web/routes/daily_jobs.py` 为启动和状态接口。`app.py` 启用调度，策略页提供保底按钮与进度展示。

应用版本清单补入启动、调度和接口文件；归档重放在原允许目录之外仅增加明确的根目录 `app.py`，仍校验路径、后缀和内容哈希。筛选、特征和执行评估关键代码身份与修改前相同，原快照不改写。
