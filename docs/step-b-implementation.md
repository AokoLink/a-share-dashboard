# 步骤 B 实施记录与运行说明

> 实施日：2026-09-30。对应[第二轮改进方案 B1—B3](project-improvement-plan-v2.md)。程序实现及自动化验证已完成；连续 10 个实际交易日的运行验收需要后续积累。

## B1：统一每日任务和结果读取

收盘后的统一入口：

```powershell
python -m pipeline.run_daily
```

任务按以下依赖执行：交易日历 → 日期／收盘检查 → 现货与新股排除名单 → 研究及对照清单 → 双价格采集 → 质量与覆盖检查 → 市场环境及板块特征 → 候选生成／冻结 → 已有信号跟踪 → 日报。

15:05 是时间门槛。除此之外，研究池内未复权与前复权日线须截止当日、至少具有 61 根历史、价格及量额单位通过校验，当日执行收盘与现货价的偏差不超过 0.5%，量额偏差不超过 3%，才允许冻结。来源不具备这些证据时跳过冻结。价格日期缺失仅标为来源缺失或交易状态待核实，不推断停牌。

每次运行有 UUID。各步骤的开始／结束时间、输入日期、结果、异常与恢复尝试记录保存到 `_analysis/daily_pipeline/runs/<run_id>/run.json`；`report.json` 留存本次日报，`latest.json` 供页面读取，`days/<日期>.json` 索引每日结果。操作系统文件锁限制同一输出根目录下同时只有一个任务执行；异常退出后锁会自动释放，原日志仍可恢复。

恢复同一天的失败步骤：

```powershell
python -m pipeline.run_daily --resume <运行编号>
```

成功步骤的留档数据先验证哈希，再复用。价格采集还有逐代码、逐价格类型的 checkpoint，恢复时重试失败、损坏或尚未截止当日的输入；执行缓存损坏时可从完整留档重建。一个上游步骤需要重新采集时，其依赖步骤重新执行。恢复要求日期、相关代码、持仓清单及运行模式一致；跨日使用新运行。相同内容冻结与观察写入保持幂等；输入改变另存冻结修订，首次快照不覆盖。

真实任务的候选生成、冻结和跟踪时间使用处理完成时的上海时间，而非任务启动时间。冻结前再次读取策略暂停／退役状态；任务处理跨过午夜时跳过前一日冻结，保留跨日原因。

只检查日历和收盘时间：`python -m pipeline.run_daily --check`。该命令不采集股票价格或冻结信号。原 `python pipeline/freeze_strategy_signals.py` 兼容入口执行同一每日任务；加 `--shadow` 时只研究观察，不新增冻结快照。

策略验证页面读取 `/api/daily-runs`、`/api/strategy-candidates` 和已有快照／观察。页面刷新、读取候选均不会访问日线来源或写入冻结。运行日志可用 `/api/daily-runs?run_id=<UUID>` 查询。市场环境页面读取每日任务保存的新版缓存。

## B2：按实际范围扩展并留档

每日范围分别保存：

| 范围 | 来源及用途 |
| --- | --- |
| 研究池 | 当日现货经过现有股票池规则筛选，最多 200 只 |
| 对照池 | 研究池，以及尚未完成观察的冻结快照内全部同池股票 |
| 已有模拟候选 | 尚未完成观察的冻结候选，单独列出覆盖 |
| 用户持仓 | 显式输入的持仓代码；未输入时记录 `not_supplied` |

可通过以下命令增加持仓价格更新范围：

```powershell
python -m pipeline.run_daily --holdings holdings.json
```

文件可为 `["600519", "000001"]`，或 `{"holdings":[{"code":"600519"}]}`。此处仅用于采集范围，不执行交易或建立账户仓位。

每只股票分别采集未复权执行价格和前复权技术价格。原始或规范化响应、采集时间、来源、复权类型、行情截止日、字段单位和 SHA256 均留档于本次运行目录。校验重复日期、日期逆序、非有限数、异常 OHLC、负量额、非交易日、未来日期、末日缺失及历史缺日。旧 pkl 不会被本次采集覆盖。

主来源为东财日线。连接失败后，同次运行切换为腾讯备选来源，记录主来源错误，避免继续逐股重复访问不可用端点。备选响应必须具有请求对应的 `day`／`qfqday` 标识；不把复权序列冒充未复权价格，也不以原价格冒充已核实前复权价格。跨年请求重叠日期若数据不一致则拒绝使用。不同板块的成交量单位按来源规则转换，并与当日现货量额核对。

真实核对还修复了原新浪现货成交量单位错误：该来源已返回“股”，不再重复乘以 100。腾讯普通股票日线成交量由“手”转为“股”，科创板返回的“股”直接保留；成交额由“万元”转为“元”。相关转换加入回归测试。

执行价格保存在 `_analysis/daily_pipeline/execution/raw_daily/`，附有来源和完整性元数据；跟踪器读取同一数据。默认采集最近约 400 个日历日，并扩大到仍需跟踪的最早冻结日。这只扩展当前运行范围，不代表 2022 年起的历史研究数据已经完整。

覆盖报告逐范围给出代码、应有数量、可读取数量、当日数量、缺失率和逐代码原因。板块当前成员、来源、匹配方式、观察日与单日有效区间也留档；未知映射仍为未知，历史成分证明保持未完成。板块指数与上证综指使用共同截止日计算描述性强度；成交广度使用当日现货。覆盖不足和来源异常进入部分完成报告。

交易状态目前只记录当时可见的名称／ST 文本及成交量代理，并明确标记停牌、涨跌停可成交性尚未核实。当前名录和这些代理不能代替历史交易状态档案或公司行为核账。

市场环境改用今后真实保存的全市场每日截面，复用原七态分类函数。至少 61 个连续交易日的全市场截面才能计算完整标签；不足时保存当日 `label=null` 和原因，不沿用旧的历史标签，也不以成交额前 200 只研究池代替全市场。初始预热期间，依赖恐慌环境的反弹策略不会生成已确认环境信号。

## B3：逐日执行进度

跟踪版本更新为 `forward-observation-v3`。新增状态包括等待入场、跳空／策略暂停导致取消、已模拟入场并持仓、等待退出、已退出、数据异常，以及交易日历未覆盖。T+1 已可记录入场与取消；无需等待最终持有期结束。每只候选的入场／取消／退出事件和当前状态随观察修订保存。

查询只使用截至观察时点已经可知的开盘和收盘信息。退出日未到时，最终毛／净收益为空；即便价格文件内存在未来数据，也不会提前使用。开盘前不读取当日开盘，收盘前不读取当日收盘。缺失入场或退出价格分别标记为交易状态／来源待核实，避免与尚未到期混淆。

暂停和退役仍阻止新增模拟入场；已入场的信号保留退出规则。已完成且具有匹配成本口径的旧观察默认保留；来源文件暂时不可读取时，不用缺失结果替换完成记录。必要时可显式运行 `python pipeline/track_strategy_signals.py --recompute`，另存重算记录。

`filled`／`entered` 记录已经模拟入场的数量；`filled_share_of_pool` 为入场数量占池规模。最终收益及毛、净基准仍分别计算，成本模型延续步骤 A。观察内容未变化时重复运行不新增数据库记录；运行时点另外留存在每次任务日志中。
