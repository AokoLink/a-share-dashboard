# P2：页面流程、查询性能与工程维护

实施日期：2026-10-01。本次对应第二轮方案的 F／P2，修复现有页面和查询的实际问题；数据与策略验收仍单独记录。

## 页面与请求

- 将“其他研究工具”的折叠范围限制为导航和说明，主板块表及各内容面板不再被默认折叠隐藏。主流程保持“市场环境 → 板块方向 → 策略候选 → 组合风险 → 验证记录”。
- GET 请求按完整地址合并尚未完成的相同请求，完成后不保留前端结果缓存。各调用者收到独立副本，失败后可重新读取。30 秒超时覆盖连接和响应解析，不自动重试写操作。
- 手动与自动刷新共享正在执行的刷新，按钮显示忙碌；隐藏页跳过自动刷新。只在板块方向视图加载板块列表，组合或验证页刷新不再顺带加载隐藏的板块列表。顶部市场与环境仍更新，旧研究工具保留原查询方式。
- 切换股票或板块详情时，较早请求的迟到响应不能覆盖最后一次选择。
- 验证记录每页取 30 条并展示全部，修复原来仅展示 10 条却跳过整页游标的遗漏。后续页只追加快照表，不重复追加版本评审；重复点击合并，读取失败保留已加载记录供重试。

## 只读查询与缓存

`GET /api/daily-runs` 和带 `run_id` 的查询默认返回摘要，包括状态、时间、步骤状态／耗时／原因、有限错误样例、覆盖数量和连续完整运行数，不携带整池逐代码输入或步骤结果。摘要的 `detail_url` 指向完整记录：

```text
/api/daily-runs?detail=1
/api/daily-runs?run_id=<运行编号>&detail=1
```

完整查询保留原 JSON 内容，已有运行文件不改写。需要完整输入的外部调用应显式使用 `detail=1`。旧运行缺少的字段不补造；完整运行的覆盖率从已有质量结果提取。

故障监控按 `failed`、`page`、`limit` 缓存裁剪后的页面，避免每次复制全部代码再分页；保留过滤后总数，每页最多 100 个代码。

报告缓存同时约束 64 项、单项 2 MiB、合计 8 MiB 的序列化 JSON 大小。大型完整记录不进入缓存，摘要单独缓存；预算不是 Python 进程内存的绝对上限，首次解析仍需临时内存。缓存返回副本，未签名后台文件按修改时间或长度失效。有预期 SHA256 的报告每次读取都核对实际字节，修复相同长度和修改时间下篡改可能命中缓存的问题。

本机 Flask 测试客户端读取已有文件的实测：

| 查询 | 修改前响应字节 | 修改后响应字节 | 冷查询秒 | 后续三次查询秒 |
| --- | ---: | ---: | ---: | --- |
| 最新运行 | 118,823 | 3,193 | 0.00223 | 0.00050—0.00063 |
| P0 大型历史运行 | 19,573,290 | 4,034 | 0.17473 | 0.00057—0.00081 |
| 故障监控第一页 | 1,316 | 1,344 | 0.00945 | 0.00047—0.00070 |

大型历史运行默认响应减少约 **99.98%**。监控增加分页大小和只读标识，响应略增；改进是避免复制整份报告并复用分页摘要。这些是本机结果，不是部署端到端延迟。大型运行源文件为 36,331,500 字节，测试前后 SHA256 相同。
