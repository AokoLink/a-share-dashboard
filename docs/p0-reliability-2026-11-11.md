# 每日运行与历史口径修订

本轮落实改进方案的 P0 基础工作。四套策略的选股门槛、分数和持有期保持当前基线，后续选股实验需独立登记。本轮不将过去补算转换为前向样本。

## 独立定时入口

`python -m pipeline.daily_scheduler --once` 检查真实交易日、15:05–23:00 时窗及持久化任务状态，然后调用与网页按钮相同的控制器。`--loop` 可独立于网页常驻检查。检查结果保存为 `automation/scheduler.json`。

Windows 安装脚本默认只显示配置，指定 `-Install` 才注册当前用户的 `Stock-Daily-Candidates` 任务。每天 15:05 至 23:00 每 5 分钟检查，登录时额外检查一次，实际启动仍受日历及收盘门槛约束。使用 pythonw 避免弹窗，无需把密码存入配置。计算机必须开机且该用户已登录；关机期间无法采集实时证据。过去缺口在页面单独列出，不能自动补记实时信号。

```powershell
./tools/install_daily_schedule.ps1 -Python C:/Users/Administrator/miniconda3/python.exe
./tools/install_daily_schedule.ps1 -Python C:/Users/Administrator/miniconda3/python.exe -Install
```

应用内调度与系统任务可并存，共用锁与防重逻辑。安装脚本拒绝覆盖同名且配置不属于本项目的任务。

## 恢复与环境数据

临时故障采用有上限的自动重试，永久数据不足和已经冻结的部分成功任务不会因轮询反复重算。每次尝试独立留档。心跳异常仅提示，不能据此杀死仍存活的工作进程。

全市场环境输入在现货确认后独立保存，个股价格或质量步骤失败不再阻止当天环境积累。连续性诊断包括要求期数、已有期数、当前窗口缺失日期、连续期数和来源未核实日期。现有历史不足时继续明确显示缺口，不降低 61 期要求，也不以当前成分或指数代理伪造历史全市场数据。

环境输入的来源与连续性校验归入 `data_features` 身份，新登记包含这一变化。原快照及原登记不覆盖。

## 历史与验证

历史候选显式区分原始留档与新版复核。原始视图保持当时名单和分数，新版复核展示独立计算及生成时间。没有原始记录时显示缺失，不能用补算冒充。

当前规则在本轮验证完成后重新登记，按已有隔离期开始接纳新的真实冻结样本。旧版失配报告和负结果保留；本轮不会因登记完成而宣称策略有效。后续规则、数据特征或执行核算发生变化，仍需新登记。

## 后续验收

连续 10 个实际交易日验收运行稳定性；策略效果需另外积累成熟的前向结果。历史全市场数据补齐、板块来源覆盖、公告采集、股票池与条件的独立对照实验仍是后续阶段，不能由本轮工程测试替代。
