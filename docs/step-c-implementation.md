# 步骤 C：板块关系、轮动与选股衔接

> 实施日：2026-09-30。对应[第二轮方案 C1—C3](project-improvement-plan-v2.md)。共用服务和接入已完成；真实来源覆盖与后续效果检验仍有缺口。

## C1：带日期的共用关系

新增 `core/sector_relations.py`、`core/sector_service.py`，板块证据、后台策略、历史评估及组合暴露读取同一份当日数据。关系包含分类类型、板块代码／名称、来源、来源名称、匹配方法、观察日、有效区间、成员数量及覆盖。支持行业、细分行业和可重叠题材三类；没有对应来源时记录分类缺失，不把行业名拆字生成细分行业或题材。

当日真实观察到的成分只对该观察日有效。精确同名跨来源和来源原生成分可进入已验证关系；人工近似、关键词和歧义匹配留在 `uncertain_relations`，不进入已确认组合暴露或板块强度条件。这里的“已验证”仅指当前关系与匹配证据，不表示历史成分已经验证。

不可变数据保存在 `_analysis/daily_pipeline/sector_evidence/blobs/<SHA256>.json`；`days/<日期>.json` 指向当日最新版本。同日更新产生新引用，原文件保留；内容相同的重复生成复用原引用。读取验证内容哈希及路径，缺失、损坏和无指定日期记录均返回未知，不能用今天的映射补昨天。来源采集时间及原始成分响应、指数、股票价格文件引用一并留档。

接口：

- `/api/sector-relations?code=600519&as_of=2026-09-30`：指定日的关系、板块特征、未知处理及证据哈希。
- `/api/sector-rotation?top=8&category=all&as_of=2026-09-30`：同日全集计算后的展示结果，支持分类过滤。
- `/api/sector`：新增板块证据与龙头角色读取后台快照；保留原指数图表和旧评分供兼容。该旧评分仍是此前的描述性评分，不是新策略的板块条件。
- `POST /api/portfolio-insights`：行业、细分行业、题材分别列出，返回逐代码关系、未知归属权重、覆盖率和同一证据哈希。行情风险计算仍保留此前接口行为。

## C2：先计算全集，再展示轮动

每日任务不再根据旧静态映射选板块，也不先取当日涨幅前几名。对来源摘要里的全部可用板块尝试采集成分及指数，失败板块保留行和具体原因；板块总数、分类缺失、当日指数数和精确成分数均可查。展示按 20 日相对上证综指强度排序，附 5/20/60 日相对收益与各自排名。上证综指仍明确标为 `sh000001`，不称全 A 市场。

指数、基准和成员使用相同决策日，先截断未来数据。指数对应周期需要完整共同交易日序列；截止落后、重复日期或缺日时，相应周期留空，不能用“共同日数量足够”冒充正确的 20 个交易日窗口。

完整广度的预设门槛为 **80%**：

| 指标 | 需要的证据 |
| --- | --- |
| 上涨比例、涨跌中位数等 | 精确当前成分，至少 80% 成分具有可用当前成交与价格 |
| 成交额前三占比、HHI | 精确当前成分，至少 80% 成分具有可用成交额 |
| 站上 20/60 日均线、60 日收盘新高 | 精确成分，至少 80% 成分具有截止同日的连续 61 根技术价格 |
| 排名变化、集中度变化 | 前一实际交易日也保存了记录；缺日不当作连续变化 |
| 龙头持续性、前日名单重叠 | 相邻实际交易日、同日行情，双方价格覆盖至少 80% |

每项都保留应有、已检查数量和覆盖率。来源失败或覆盖不足时不展示完整广度，不以零填补缺失。“启动观察、内部扩散、明显分化”等标签仍是描述性状态，不是经过收益验证的信号。

## C3：板块条件进入两条选股路径

后台 `core/strategy_service.generate` 与历史 `pipeline/evaluate_strategies.py` 均调用 `sector_relations.feature_for`，将 `sector_rel20` 传给原 `strategies.screen`。其单位为百分数，与板块相对收益报告一致。

确定归属后，优先使用细分行业，其次行业，再次题材；同层多个归属采用等权平均，所有被选归属都须具有同日、可核查的 20 日指标。不选择事后最强的一个板块，也不以题材强度替代一个缺失的已知行业。归属未知或指标无法验证时，突破保持原有“研究候选、不加板块分、附待核实说明”规则；已确认超额非正时不通过突破板块条件。回调、反弹未设置此项规则，候选标为 `not_applicable`。

每只候选和冻结研究池保存关系、选用板块、特征日期、聚合方法、缺失策略、指标及证据哈希。冻结记录还保存不可变板块快照引用与板块代码版本。后来成分发生变化不会修改旧记录；筛选身份升级至 `stage2-online-screen-v4-sectors`，已有版本记录保留。

历史评估也从指定日快照得到同板块对照范围。该历史日没有关系证据时，同板块对照为空并带缺失说明，不能继续把静态当前映射作为历史事实。历史评估默认输出新文件 `stage2_strategy_eval_v3.json`，保留原 v2 报告。在线与离线整个股票池资格顺序的统一、条件加入前后的收益实验仍归步骤 D，本次仅统一板块输入及其处理。

价格领涨不再由页面额外请求最多 10 只股票，而是检查后台已采集的全部成分价格，报告有效数量／完整成分数量及完整、部分或未知状态。比较同日 5/20 日收益和相对板块表现，保存普通成员中位数、领涨与普通成员差距、名单重叠和跟随广度。成交核心单独报告成交额覆盖及份额分母；产业核心仍需财务／业务证据，保持空值。

目前成员技术价格来自 B 的研究、对照、持仓及待跟踪候选采集范围；没有假定覆盖全市场全部板块成员。扩大到所有已采集成员已经解除 10 只上限，尚缺的成员价格明确计入缺失率。

## 操作与实际验证

日常统一入口已接入 C：

```powershell
python -m pipeline.run_daily
```

仅重建既有真实留档的板块证据，不访问来源、不冻结信号：

```powershell
python -m pipeline.build_sector_evidence --run-id <每日运行编号>
```

当日收盘后，复用该日已留档股票收盘价格并重新采集完整板块集合：

```powershell
python -m pipeline.build_sector_evidence --run-id <当日每日运行编号> --refresh --workers 6
```

独立采集记录保存到 `sector_runs/<UUID>/run.json`，覆盖摘要保存到 `sector_evidence/latest_report.json`。跨日、未收盘或未来档案不能用此命令冒充当日观测。独立板块刷新不新增策略冻结，不计入 B 的连续完整运行验收。

自动化回归：**494 项通过**，4 条原有回测空样本 NumPy 警告；JavaScript 语法检查、差异空白检查通过。验证了精确／近似映射、三类暴露、80% 门槛、超过 10 个成员的领涨识别、日期缺口、排名变化、持续性、网页只读、同输入两条路径的板块条件、未来数据隔离、同日幂等及旧冻结引用保留。
